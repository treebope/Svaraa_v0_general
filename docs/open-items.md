## Switching from mocks to the real backend

See `docs/integration.md` for the step-by-step guide and the status of every area. Today everything runs on the mock backend inside the app, and Google sign-in is mocked twice: the button returns a fake token (`flags.googleSignIn = 'mock'`) and the mock backend accepts any token.

After setting `EXPO_PUBLIC_API_URL` to the Railway dev URL, switch one area at a time with its switch in `config/flags.ts` (`auth`, `household`, `notifications`), or one endpoint at a time with `EXPO_PUBLIC_REAL_ENDPOINTS` (see `.env.example`), in this order:

1. **Phone OTP:** `POST /api/v1/auth/otp/request` and `/otp/verify`. Needs no Google setup.
2. **Session:** `GET /api/v1/users/me`, then `POST /auth/refresh`, then `POST /auth/logout`. Check the 401 refresh and retry against the real server, and the real error codes.
3. **Google, last** (see the setup steps below), then `POST /auth/google`, and `POST /auth/mobile/request` and `/mobile/verify` for "Add your phone".

### Google setup steps

1. Backend deployed with `GOOGLE_CLIENT_IDS` set (see Pending backend).
2. In Google Cloud, create OAuth clients: web, iOS (bundle id `ai.svaraa`) and Android (package `ai.svaraa`, with the app's SHA-1 from the EAS build).
3. Test the backend alone first, with its `/dev/google-login` page.
4. Make a development build (EAS, needs the Expo login): Google sign-in cannot run in Expo Go.
5. Add native Google sign-in in `services/auth/google.native.ts` with a `.web.ts` stub, and set `flags.googleSignIn = 'native'`. The app already saves the Google name as the profile name after sign-in.
